§5创新③：CNN 数据流映射——384 个宏怎么排布

📐 本节目标

理解：① CNN 层计算的基本参数；② 四种映射情形的空间排布与时间循环划分；③ 为什么 Case 1 最理想、Case 3 性能较差、转置卷积需要特殊支持。

5.1 CNN 层计算回顾

一个卷积层处理 3-D 输入张量 + 4-D 核张量，在每个输入窗口上做矩阵乘法 → 3-D 输出张量。参数：输入尺寸 (IX, IY)、输入通道 C、输出通道 K、核尺寸 (FX, FY)。与传统矩阵乘法不同，相邻输出像素共享大量输入像素 → 可以优化数据复用、减少搬移。HUNBN 支持普通卷积与转置（上采样）卷积，主要差别在输入取数模式：普通卷积窗口内所有像素与核卷积；转置卷积先插零再上采样。

5.2 四种映射情形（论文 Fig.9）

Case 1：FX=FY=3, C=32, K=32（基石配置）

  • 384 宏排成 3×4×32 星座：簇级映射 FY=3、C1=4、K=32 三个循环；宏内映射 FX=3、C2=8（宏做 24 个向量乘 → 支持 FX=3 和 C=8）；
  • OX/OY 在时间域循环（存 I/O SRAM）；
  • 最优之处：恰好用完一个 DIMC 地址 → 整个层计算期间权重在该地址反复复用 → 宏级能效最大。

Case 2：FX=FY=3, C>32, K>32（扩展配置）

  • 层需要多行 DIMC → 存连续地址，C/K 子集时间循环（例：C=64, K=64 用 2 个地址）；
  • weight-stationary 数据流：K0/C0 外层时间循环 → OX/OY；
  • 两大收益：① 减少权重读频（同步 DIMC 操作的惩罚小）；② 滑动窗口利用 FX 方向数据局部性 → 输入复用↑。

Case 3：FX/FY>3（如 5×5）

  • 核按 3 分割取整：5×5 → 上 3×3 + 2×3、下 3×2 + 2×2 四部分；子核存连续 DIMC 地址，小部分补零防误算；
  • 簇内宏分成高利用率（灰）与低利用率（红）——子核映射欠优 → 性能低于 Case 1/2。

Case 4：FX=FY=4 转置卷积（C=18, K=32）

  • 宏排成 4×3×32 星座：簇级 FY=4、C1=3、K=32；宏内 FX=4、C2=6（单地址）；
  • 充分利用 DIMC 内存与 MAC 资源；
  • 但输入通道数通常是 32 的倍数，与最优 C=18 不对齐 → 输入/输出搬移管理复杂化 → 需要 §6 的特殊支持。
💡 核心权衡：利用率 vs 面积

支持“所有映射”可消除欠利用，但会增大芯片面积、降低面积效率。HUNBN 的选择：覆盖最常见的情形（3×3 卷积、大通道、大核、4×4 转置），接受大核拆分（Case 3）和点卷积（1×1）的欠利用。实测中：U-Net（大量 3×3）达峰值 80%，ResNet8 57%，MobileNetV1/DS-CNN（大量点卷积/深度卷积）只有 ~2 TOPS/W——这就是“数据流匹配度决定系统能效”的直接证据。
