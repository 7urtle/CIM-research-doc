§6创新③：ODFC——轻量片上微调核心

📐 本节目标

理解：① 为什么边缘芯片需要片上微调；② 多轮数据流怎么用面积换时间；③ 保损失 FP 加法解决对齐损失；④ 微调恢复精度的实测。

6.1 动机：环境变化让精度暴跌

边缘设备经常面对变化的环境（光照、天气）→ 测试样本与训练集差异 → 精度大跌。用 MNIST 训练、MNIST-M 测试模拟背景变化：精度从 99.1% 暴跌到 13.8%。先前 FP-CIM 不支持片上微调 → 需要能训练的小面积硬件。

⚠️ 训练硬件为什么难做？

训练的算法复杂度远高于推理（梯度反向传播、权重更新）→ 电路复杂；但边缘芯片面积受限。关键缓解：微调只需少量 epochs（远少于从头训练）→ 可以用“面积换时间”的折中。

6.2 多轮数据流（论文 Fig.13a）

ODFC 用 128 轮顺序更新整个 CIM core 的 128×16 权重（每轮只更新 16 个）：

  1. 权重读：从 CIM core 读出 16 个权重尾数，归一化为 BF16；
  2. 权重更新：ODFC 计算在 k 个周期内完成（k = 梯度向量长度）；每周期取 1 个 X 和 16 个梯度，更新前层权重；
  3. 梯度计算：k 周期后算出更新后的权重和偏置；
  4. 权重写：对齐后写回 CIM core。

→ 每轮只更新 16 个权重 → 电路面积大幅降低。

6.3 硬件优化（论文 Fig.14/15）

  • 时分复用：BF16 乘法器和加法树在不同计算阶段共享 → 面积再省 10%；
  • 保损失 FP 加法：多 FP 数累加时，大数加小数 → 小数移位后尾数可能变 0 → 三个数之和为 0（Fig.15a）。解法：把对齐误差保留并在下一级加法再处理 → 应用于 16×BF16 加法树（Fig.15b）→ 降低多级求和损失。

6.4 ODFC 实测（表 III + Fig.23/24）

  • 规格：0.037 mm² · 180 MHz（与 CIM core 同频）· 16 ops/周期 · 2.88 GOPS @BF16（0.9V）；
  • 能效：面积效率 0.078 TFLOPS/mm²、能效 1.71 TFLOPS/W（post-layout）；
  • 微调恢复：MNIST→MNIST-M，ODFC 训练 10 epochs → 精度 13.8% → 84.3%；
  • 层级分析（表 IV）：6 层 multiply-less NN 微调总延迟 14.3 ms、总能耗 18.1 µJ；训练能效 1.32 TFLOPS/W（低于推理，但微调远少于推理 → 系统级影响可忽略）。

💡 本节小结

① 环境变化 → 精度暴跌 → 需要片上微调；② 128 轮顺序更新（每轮 16 权重）→ 面积换时间；③ 时分复用（−10%）+ 保损失 FP 加法；④ 实测：13.8%→84.3%（10 epochs）、总能耗 18.1 µJ。
