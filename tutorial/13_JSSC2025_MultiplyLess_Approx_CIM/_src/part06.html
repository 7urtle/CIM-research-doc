§6创新③：位串行比较 + 稀疏感知的提前停止（Early Stop）

📐 本节目标

理解：① MinMUX 怎么“锁定”最小值；② 8T SRAM 专用读端口如何在权重位为 0 时省电；③ 比较一旦分出大小就提前停止读权重位（1.8× 读端口省电）是怎么做到的。

6.1 MinMUX：比较结果驱动的透传选择

论文 Fig.8 的 MinMUX 电路：OUT 和 OUTB 是位串行比较的结果节点，初态 OUT 预充到 VDD、OUTB 放电到 VSS。比较过程：

  • 尚未分出大小（当前位相等）：OUT/OUTB 保持电荷，MinMUX 继续把权重位传给累加器（默认先走权重路径）；
  • 权重更小（某位 ACT=1, W=0，即 x 该位大于 w 该位……注意 MSB 优先）：OUT 放电到 VSS、OUTB 被钳到 VDD → MinMUX 从此一直输出权重位；
  • 激活更小：OUTB 放电到 VSS、OUT 被钳到 VDD → MinMUX 从此一直输出激活位。
💡 关键性质：一旦分出大小，min 的“身份”就锁定了

MSB 优先比较的经典性质：最高位决定大小，之后位无论是什么都不影响结果。所以比较器只要“断言”一次（某位分出胜负），后续周期的 min 就固定是 x 或 w 其中之一——MinMUX 变成纯透传，不需要再比较。这是位串行方案能“提前停止”的根本原因。

6.2 专用 8T SRAM 读端口：权重位为 0 时保持预充

论文 Fig.9 画了 8T SRAM 的专用局部读端口：当被选中的权重位是 0 时，局部读位线（local read bitline）保持在预充电压——不放电、不耗动态功耗。反之权重位是 1 才需要放电。

结合 §4.3 的权重截断：预计算后权重里 0 的数量暴增（86× 稀疏度提升），所以大多数位读出来都是 0 → 大多数周期读位线都不放电 → 读功耗大幅下降。这是“算法近似 → 电路省电”的直接转化。

6.3 提前停止：激活被选中后不再读权重

论文 Fig.10(a) 的机制：当比较断言“激活更小（min = x）”后，OUT 被充到 VDD，读端口停止对局部读位线的重复预充——因为权重位不再需要被读取（MinMUX 直接输出激活位）。图中蓝色标记的权重位：不需要再预充和读取。后续周期 MinMUX 直接把激活位输出给 MinACCU。

⚠️ 提前停止的收益来源要分清

这里有两层省电：① 权重位=0 保持预充（稀疏感知，随时生效）；② 激活被选中后停止读权重（比较断言后生效，只发生在 min=x 的情况）。两者都依赖位级稀疏/比较特性，都不需要稀疏训练。论文 Fig.10(b) 报告专用读端口设计带来 1.8× 功耗降低（读端口层面）。

6.4 小结

  • MinMUX：比较断言后锁存 min 身份 → 纯透传；
  • 读端口：权重位 0 → 位线保持预充（配合 86× 稀疏度）；
  • 提前停止：min=x → 停止读权重 → 读端口省电 1.8×；
  • 三层机制全部“白捡”自算法近似，不需要额外稀疏训练/硬件。
